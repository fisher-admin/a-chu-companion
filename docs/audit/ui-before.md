## 两个需要一起调整的阅读契约

现有 [EditorTests](../../Tests/EditorTests.swift) 验证“长文内容改变后返回头部”，符合此前完整新回复从开头阅读的需求。新增增量模式时，应把它细分为：新回复首次显示回顶；同条回复追加或修订保持当前位置；用户主动“从头阅读”才回顶。不能只删掉旧测试或统一改为跟随底部。

每个 Code 完成分段仍单独显示一条，最近十条仍按完成分段计数。较小的内部翻译切片不应变成十条新气泡，也不应让同段修订移动到列表底部。

原文预览不是翻译的替代功能。状态应分别说明“等待片段稳定”“排队翻译”“正在翻译”“译文已更新”或“翻译失败”；稳定片段的中文无需用户再次点击，也不能等整轮结束才出现。阶段译文可见不意味着整条消息/整轮任务已经完成。

## 真实验收中需要采集的画面

使用专用合成内容，保持修改前后相同尺寸、字号与主题，记录：空白主窗、连接状态、阶段性原文、已有中文加待译尾部、工具等待、翻译失败、长文中段选区、额度旧数据、设置页，以及 610 宽、短屏幕、三种字号和深浅色组合。
