# CLI快捷键直接连接修订记录

基线为1.1.8/build69、`6019d3b`。用户真实反馈：仍不能自动填入，主界面只有读取历史回复和仅翻译；用户要求在CLI输入区按快捷键直接连接，不选择会话。此反馈作为build69真实验收失败保留，不能以旧模拟通过覆盖。

## 问题与修订

1. 捕获时必须已有页脚，而入口配置及刷新在捕获之后，首次页脚较迟会丢掉表面；`try?`又丢弃原因。修订为立即保存唯一焦点文本表面，随后核对同一表面的强标记和进程；未核对前不启用输入。
2. 快捷键路径立即打开选择页，容易只连接回复来源。修订为快捷键直接自动核对当前窗口，全程不弹来源选择、不按最新报告猜测。已有补充只读选择不成为必经步骤。
3. 已选来源的输入身份迟到后不再尝试绑定。修订为仅重新核对同一已选来源与原捕获表面，不切换到别的来源。
4. 终端末尾空白行会把页脚挤出末尾12行判断。合成检查确认旧实现失败；只去掉末尾空白行，普通shell或选择提示仍阻止绑定，不放宽非空草稿和身份检查。
5. 输入连接原因单独显示，不被回复/额度状态遮盖；发送入口一直显示，未绑定时禁用并说明原因。状态只含判定原因、界面计数，不保存终端原文或凭据。

## 真实Terminal验收

1. 保持当前CLI消息输入区为空、输入区与底部页脚可见，在该窗口用实体Control+Option+E直接连接；不点来源列表。
2. 伴侣应不弹会话选择，顶部不标只读，发送入口可用。若失败，顶部独立连接提示应给出具体原因及安全计数，而不是只读成功提示。
3. 使用公开短句“请用两句话解释交叉验证。”，核对译文填入同一CLI输入区且只发送一次；正式回复读取及中文回译另行确认。多行、表格及折叠长文仍需终端确认发送。
4. 多个CLI窗口/分屏、切焦点、已有草稿、退出和账户切换分别核对；未核对到原输入区时保持禁用，不能发向普通shell。
