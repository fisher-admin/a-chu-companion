# build77：由伴侣管理网页额度接口

用户要求不再承担Chrome开发者设置、加载目录或填写扩展ID，只参与必要授权。旧的build75/76手动入口流程撤回；保留其实际读取通过、额度未通过和工具对内部管理页的拒绝。没有改写这些旧结果，也没有通过其他工具访问被拒绝的内部页面。

## 实施

伴侣打包并监督最小额度模块和只监听127.0.0.1的服务。正常设置只提供授权、连接已指定网页、补充刷新和撤销。当前利用本机已安装的Tampermonkey；仅安装元数据不证明运行许可，必须以实际模块心跳和额度验收为准。正式Chrome商店组件尚未发布；没有静默安装本地CRX、改企业策略、浏览器私有设置或读取Chrome Safe Storage。

准备授权时，只有一个可用浏览器可直接作为安装载体，不必先绑定输入框；多个载体不猜，已手选的浏览器不能替换。安装载体不代表聊天目标或当前账户，实际额度仍须用户指定网页的唯一焦点证明。没有已选目标时，“连接已指定网页”禁用。

安装能力五分钟、一次性；长期密钥在隔离存储生成，本机私有文件持久保留。它不是Claude登录凭据。接口要求认证签名、正确Host、请求限长限速、应用代次和递增序列，无CORS；拒绝盲表单和未知字段。短时焦点挑战只接受指定网页的唯一可见聚焦实例，不按地址猜标签。最多等1.4秒后正常打开面板，额度失败不影响发送。

网页刷新保留标签身份，页面实例另行校验。接口读取账户、额度、账户，前后身份一致才发布；只传遮蔽账户、指纹及额度。账户往返切换使用新证据代次，防止与迟到报告混淆。短时心跳失联先隐藏旧额度，再由原授权标签恢复；换输入来源或撤销授权不能由旧标签恢复。

- Node额度模块14项通过：真实Web Crypto签名，合成Claude接口，同源凭据、遮蔽身份、前后账号变更拒绝、无Cookie及正文。

## 最终安装与准备检查

正常本机固定签名构建并安装最终build77成功。严格签名核验通过，与build76指定签名身份一致；安装程序及9个桥接资源与构建包逐一一致，无Python字节码缓存。没有修改证书信任、辅助功能授权或浏览器设置。

正式程序已打开，新设置没有目录、ID或安装载体选项。尚未选择网页输入时，“连接已指定网页”和刷新禁用；“连接网页额度”可独立准备安装。从伴侣点击该按钮后，浏览器出现正常“安装用户脚本”授权页，证明安装准备不再要求先绑定输入；这是授权待确认状态，不是模块已获准运行或额度已读取成功。未通过工具打开扩展内部管理页。

## 真实验收

尚未取得正式安装后的模块运行许可与真实额度。本机已经存在运行组件，但不能据此报告其已启用或当前账户接口已成功。验收仅读额度，不发送Claude消息；用户只确认正常安装授权。若组件不能运行，不再要求Chrome技术配置，不把桌面账户或独立内置登录当作网页当前账户。

真实检查顺序：安装身份连续性及界面 → 正常安装授权 → 原手选网页焦点配对 → 当前遮蔽账户、五小时／每周额度及重置时间 → 补充刷新、模式导航、失联恢复。涉及真实退出／换账户时不擅自改变用户登录，使用已授权的测试条件或单独交接该账户动作。
