# build78：原生网页额度读取

日期：2026-10-08。保留build77提交`1b53d14`、原失败／未完成状态和旧源码测试。该方案因用户明确要求不安装浏览器组件而撤回；当前正式构建排除`ManagedWebUsage.swift`，仅打包CLI的`Bridge/bridge.py`。

## 实现

- 额度只访问手选的应用与物理窗口，或显式发现的唯一官方Usage窗口；不猜浏览器品牌、最近配置或其他端账户。发现额度窗口不建立发送目标。
- 用同一窗口侧栏账户菜单在读取前后核对唯一完整邮箱；它仅短暂用于本机哈希，发布遮蔽邮箱与指纹。身份不明／变化或页面未恢复不发布。
- 通过原有网页控件打开Usage、点击Refresh、读取明确分区，关闭设置并恢复原页。支持英文、简体、繁体；控件与文字冲突拒绝，付费credits、按产品和按模型分配不作总周额度。
- 套餐来自实际Usage标签；未提供显示未识别，不凭Pro／Max假设删除网页实际提供的额度项目。重置说明原样保留，不猜精确日期。
- 自动请求要求所选窗口仍在前台，且发送／初始回复绑定未运行；显式读取才允许激活原窗口。失焦停止后续操作，不抢回窗口。快照不是持续后台API查询。
- Usage遮挡期间只跳过同窗回复扫描，保留读取连接和译文任务；恢复后继续。此前未完成的扫描结果／错误按代次丢弃，不把设置页误判成Claude会话关闭。
- 显式读取重新关联相同额度窗口，断开再读取可恢复显示。网页额度断开不删除独立手动session。额度开始事件仅隐藏旧值，不取消自身请求。
- 手选发送租约、中文翻译、粘贴和一次Return逻辑不变；额度模块不发送消息、不操作剪贴板、不重选消息输入框。

## 已知验证边界

- 英文Chrome Usage实际读取已验证；简繁页面结构已观察，最终解析以合成数值回归验证。其他浏览器、其他套餐及真实切换账号本轮未操作。
- 后台零激活、失焦取消、账号切换、恢复失败和同窗回复暂停通过模拟；本轮不发送研究消息，不声称已完成真实新回复后的自动额度刷新或跨程序发送验收。
- 常驻后台无干扰获取最新额度未实现；后台显示最近核对快照，主动刷新可更新。这是界面读取方案的明确边界。
- 旧网页组件与测试保留在仓库历史，正式应用既不打包也不启动。本机没有为这次修订安装新脚本／扩展或提取浏览器登录凭据。
