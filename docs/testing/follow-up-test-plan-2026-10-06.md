# A畜伴侣后续完整测试计划

日期：2026-10-06。范围为 Claude 桌面 Chat、桌面 Code、Chrome 中的 Claude 网页版及 Claude Code CLI，中文为核心，目标语言为英文、德文、日文和韩文。本计划安排后续检查，不启动新的真实请求、安装或账号变更。真实测试按用户后续指令分批执行。

## 当前基线和优先事项

最近一次验证基线是 1.1.7 build41。其 23 组、329 项应用回归及 14 项本机 HTTP 检查已通过；18 项专门检查覆盖此次段落断行修复。[依据：段落报告第 25、31–32 行](paragraph-layout-2026-10-06.md#最终安装与已有-claude-回复复核)。本计划不将旧方案中的 build33/build37 状态当作当前版本结论，也不覆盖旧报告。

后续先处理三项明确不足：系统翻译曾改变文件名；Gemini 表格中的统计术语仍不够精确；一个阶段初次翻译失败，重试后才完成。[依据：段落报告第 33–35 行](paragraph-layout-2026-10-06.md#最终安装与已有-claude-回复复核)。后台专项此前只观察了已结束会话的状态保持，没有证明其他程序在前台时新回复仍持续读取和翻译。[依据：段落报告第 37 行](paragraph-layout-2026-10-06.md#最终安装与已有-claude-回复复核)。

桌面 Chat 已有三轮真实学术交流记录，但同一最终版本无需重绑的连续交流仍应复测；网页完整往返及其余专项不能由桌面结果代替。[既有总方案](real-environment-test-plan.md#本次验收范围完成条件与时间安排)、[Chat 记录](real-academic-chat-2026-10-05.md)、[Code 补测记录](real-code-supplement-results-2026-10-06.md)。

用户在本次计划中明确加入 Claude Code CLI，故将其伴随读取、连续交流、额度与配置保护纳入正式测试范围。既有实现记录说明 CLI 桥接默认关闭、默认仅接 statusLine，正文事件须先确认当前 CLI 版本支持；受控进程自动发送尚属后置能力。[CLI 当前实现边界](optimization-implementation-report.md#实施结果与边界)。CLI 测试不能预先记为完整读取或自动发送可用。

以上是建议的分批上限，不是已经发生的调用量，也不代表免费额度保证。执行前核对当前来源、专用会话、翻译器、目录和实际预算。失败、重试、连接检查、表格语境和分块全部计数；重用已有回复的翻译请求同样计数。到任一上限便停止新的测试调用并保留未测项目。必须先验证计数及停止操作有效，不能依靠测试结束后追算来控制预算。

不为制造 429 而消耗真实配额。网络错误优先在本机接口模拟；真实断网或恢复仅作用于明确选择的测试环境，不改用户日常代理规则。真实新增测试须有用户指令；本次列计划不构成执行授权。

## 正式范围的全部测试组

### 1 翻译准确性和文字结构

**T01 翻译角色和语义准确性，优先修复再测试。** 固定中文及外文参考语料，包含研究提问、否定、先后顺序、未实施的研究、数值、单位和统计术语。对系统翻译、Gemini 和已选择的兼容 AI 分别检查。Gemini 及兼容 AI 面对“请解释研究假设”只能翻译这句话；不得给出假设、执行命令或代答。统计词使用有明确语境的参考译法；例如语境明确说明 Spread 是 standard deviation 时，不能译成传播或泛指分布。通过标准：提问、否定、数值和限定条件完整；参考语料无代答；术语符合该语境。自动检查只能证明明确的文字契约，语义还须人工对照，不能用模拟接口证明供应商质量。

**T02 段落、表格和保护内容。** 使用句内文件引用、链接、强调文字、真实多段、列表、引用、代码围栏、行内命令、路径、URL、占位符和四列表格。另测长段分块、合法多行单元格及跨批次未闭合代码。通过标准：同段不被拆成额外段落；真实段落和列表边界保留；代码、文件名、路径、URL、占位符逐字一致；表格行列和数字对应；语境不能进入表头或单元格。窄窗自然折行与原文硬换行分别检查。系统翻译的文件名问题须在此项闭环，不以 Gemini 通过替代。

**T03 原文立即显示和稳定阶段及时翻译。** 本机使用分阶段假回复及可阻塞翻译器；真实 Code 使用至少三个正式阶段、多个运算或工具步骤的学术任务。记录正文可读、采集收到、原文可见、稳定、翻译提交、中文可见及整轮结束时间。通过标准：原文显示不等翻译；稳定正式段自动进入翻译；首阶段中文在整轮结束前可见；后续阶段逐条显示；运行提示不混作正式正文。翻译失败必须显式标出，不能把原文出现算成中文成功。若 Claude 未形成阶段，则记为测试条件未形成。

### 2 桌面连续交流和后台读取

**T04 同一版本连续多轮。** 桌面 Chat 和 Code 各连续两轮，不安装、不重启、不重新绑定；交替从伴侣发送中文和从 Claude 原窗口直接发送英文。通过标准：每一轮都自动读取并完成中文翻译；不漏轮、不重复；新阶段独立计入记录；没有只靠手动历史按钮取得的新回复。前后不同 build 的结果不拼成连续通过。

**T05 后台和窗口生命周期。** Claude 正在产生新阶段时，将其他程序置前台；再分别检查伴侣隐藏、Claude 遮挡或最小化、切换 Space、源窗口关闭重开。锁屏、睡眠唤醒由用户另行安排。通过标准：来源仍暴露正文时，原文和中文实际持续更新，不抢焦点；来源暂不可读时明确提示并能恢复，不拿缓存或“正在读取”标签当新内容证据；恢复不重复追加、不自动停止监控。每种窗口状态分别给结论。

**T06 自动发送和目标保护。** 检查仅粘贴、回车发送、Command+回车、快速重复提交、翻译期间换会话或输入框、目标失效以及剪贴板恢复。通过标准：仅粘贴不发送；所选且源软件支持的发送键能发送一次；未完整译文不发送；目标不匹配时阻止发送并保留内容；不覆盖用户新复制的剪贴板内容。错会话和重复发送必须为零。

**T07 实体键盘和中文输入法。** 用实体输入法检查选字回车、Shift+回车、多行粘贴、连续按键和忙碌时提交。通过标准：选字不误提交；换行正确；忙碌时不产生重复请求；连接后伴侣输入框可以正常获得焦点。全局连接快捷键需要实体键盘时，提供可点击的“已连接”按钮，并在点击后实际核对目标，不要求用户手打确认文字。

### 3 故障、来源隔离和历史

**T08 翻译故障和恢复。** 本机覆盖 401/403/429、等待时间、503、断网、超时、空结果、截断、重定向、取消及晚到结果。真实检查短语料失败后的恢复，不通过大量请求强造故障。通过标准：原文和已完成中文保留；失败原因及重试入口明确；遵守等待时间；不永久转圈、不重复拼接、不自动换云服务。重试成功与首次无失败分别记录。另用慢翻译器确认新的稳定段不会因前一长文一直得不到调度。

**T09 切会话、停止、清除和并行返回。** 在读取或翻译中切会话、切目标语言、换翻译配置、停止再恢复、清除记录，注入乱序回调。通过标准：自动跟随同窗新会话；旧结果不进入新会话；停止后的旧结果不显示；清除后旧记录不复活；草稿保留；同一阶段修订不重排或清空已有中文。真实操作只在专用测试会话之间切换。

**T10 历史选择、缓存和十条记录。** 滚动 Claude 历史，让视野内同时出现多条正式回复，再选择指定条目；对缓存条目重新选择；本机生成至少十一条完成译文，另测退出重开。通过标准：列表只包含当前可见且可选的正式回复；译文与所选原文对应；已缓存结果不再调用云接口；运行内只保留最近十条完成记录；清除有效；退出后记录清空。真实记录不足十一条时，真实超量检查保留未测，不能为凑数擅自追加消息。

### 4 长文本、语言和设置

**T11 字数边界和长文完整性。** 本机测试输入 9,999／10,000／10,001 字符，外文回复 49,999／50,000／50,001 字符，包含中文、emoji、换行和混合语言；检查分块首尾及末尾标记。通过标准：计数符合界面说明；上限内完整处理；超限明确提示并保留全文，不静默截断或半截发送；长内容不使界面失去响应。50,000 字符在线翻译或真实发送单独授权，主要边界测试用模拟完成。

**T12 四种语言双向。** 分别进行中文到英文、德文、日文、韩文，以及对应外文到中文；切换时保留未完成任务作为隔离检查。通过标准：输出语言正确；核心中文界面不变；含义和保护内容符合 T01/T02；旧语言任务不写回新任务。每种语言和每家翻译器独立记录，不用英文一项代表四语全部通过。

**T13 翻译服务配置和密钥隔离。** 检查系统翻译、Gemini、已选择的兼容 AI，涵盖模型保存、接口修改、配置快速切换、旧配置迁移和钥匙串暂不可用。跨来源认证测试只用假密钥及本机接口。通过标准：新地址不会收到旧来源密钥；Gemini 保持原生接口和指定模型；凭据不可用与未配置分别提示；模型、语言等保存正确；密码框、日志和错误内容不泄露密钥。表格语境支持须逐个翻译器验证，不能把 Gemini 的实现当作所有翻译器已具备。

**T14 设置记忆和系统语言包。** 保存语言、字号、翻译方式、模型、发送选择；重开及沿原签名升级；已有语言包时重复使用，未安装或离线时单独检查。通过标准：选择保持；已安装且系统仍认定有效的语言包不重复要求安装；首次准备有明确状态、可取消和超时恢复；不通过删除语言包制造测试条件。

### 5 阅读和界面

**T15 长文阅读、字号和紧凑布局。** 检查默认窄窗、最小窗、较宽窗和短屏，12／14／16 三档字号，长中文首次显示、用户向上阅读后的续写、选区和复制。通过标准：默认中文 14；首次显示从回复开头开始；同条更新不抢用户阅读位置；复制首尾完整；译文利用可用宽度；顶部三个操作集中、额度条可见、底部单排，无挤压遮挡或不可操作按钮。表格的横向滚动和正文纵向滚动分别检查。

**T16 主题和辅助使用。** 检查系统浅色／深色、透明度设置、提高对比度、VoiceOver 和键盘导航。通过标准：顶部随主题变化；文字、按钮和焦点可辨认；菜单栏仅显示所需图标且有可读名称；错误不只依靠颜色；字体和玻璃效果不影响阅读。

### 6 额度、权限和自检

**T17 Claude 额度来源、刷新和账户范围。** 对照同一账户官方可见用量，检查百分比、进度条、五小时／周窗口、reset 及所在时区；覆盖新回复触发、手动刷新、冷却、缺字段、源关闭、重复旧样本和登录来源变化。不同账户用本机样本或用户提供的测试账户，不退出当前工作账户。通过标准：数值与确认来源一致；来源和时间明确；不存在的窗口显示未知或不可用，不补假 0%；失败保留带时间的旧值；旧样本不能伪称刚刷新；不同账户不串值；取额度不发聊天消息。窗口以官方来源实际字段为准，不单凭 Pro／Max 名称推断。本计划不纳入 API 账单。

**T18 权限、签名和升级连续性。** 沿原签名检查安装、重启、升级和可恢复备份；权限开关的运行中变更另选测试时段。通过标准：普通重开或沿原身份升级不重复要求授权；授权变化能在运行中识别；撤销后说明受限、恢复后不必靠重启才生效；草稿和设置保留；升级失败能恢复旧程序。需要重新绑定目标与重新授权分别记录，不重置其他应用权限，不删除 Claude 登录。

**T19 自检和启动响应。** 测冷启动离线、重复打开设置、缺少可选桥接、服务暂不可用和旧检查晚到。通过标准：界面可操作；重复检查合并；可选功能未配置不阻断已经可用的翻译；填有模型或 key 不冒充生成成功；被动自检不产生翻译推理请求；旧结果不污染当前配置。

### 7 网页、稳定性和开源发布

**T20 Chrome 网页完整往返。** 先验证现有网页读取路径，不以安装扩展作为前提。专用 Claude 网页会话连续两轮，伴侣发送与网页原窗口直接发送混用，再测历史、切会话、换标签、关闭或刷新页面及后台恢复。通过标准：完整输入、发送、自动原文和中文流程成立；只读取绑定来源；不混其他标签；网页重建后正确重同步；页面不暴露正文时明确受限。网页版独立于桌面验收。若确需扩展，再进入 X01。

**T21 性能和持续运行。** 先做本机 30–60 分钟重复回放、长文、切换和取消；真实来源作同条件采样。记录采集耗时、稳定后排队、翻译耗时、CPU、内存、队列峰值及请求数量。通过标准：无崩溃、无队列持续膨胀、无重复请求风暴；取消和恢复正常；后台新内容检查满足 T05。性能沿用既有方案的目标：受支持前台桌面原文 P95≤1 秒、活动网页桥接 P95≤500 毫秒、已预热系统短段翻译尝试 P95≤2 秒，最后一项不包含约三秒稳定确认。每种条件至少三十个有效样本才报告 P95；云服务耗时和失败率单独实测，不承诺固定速度。[计时与性能口径](real-environment-test-plan.md#7-性能请求量与通过判定)。AX 网页与扩展采集分别记样本，不互相代替。

**T22 凭据、隐私和仓库检查。** 检查当前文件、Git 历史、日志、截图、发布包及源码归档；使用合成秘密验证过滤。通过标准：不包含真实 API key、Claude session／Cookie、账户标识或私人聊天；私有运行数据被排除；日志只含必要状态和脱敏数量；发布内容与审查清单一致。模式扫描与人工复核并用，扫描通过不称为所有形式秘密绝无泄露。测试日志不保存其他工作会话的正文。

**T23 清洁安装、构建和发布准备。** 在临时清洁检出及可用的额外测试机器上，检查说明、构建、CI、首次启动、安装和升级回退；核对 MIT、双语文档、版本号、更新历史、贡献与问题报告说明。通过标准：干净源码可构建及运行适用检查；开发者个人证书或凭据不是源码构建前提；包内名称、图标和版本一致；实际支持系统／浏览器矩阵如实列出；新结果追加，旧失败和版本历史保留。额外机器未取得时明确未测。发布上传及公开 release 在完成审查后另按用户指令执行。

### 8 Claude Code CLI 正式测试

**T24 CLI 版本能力和接入。** 先只读核对官方程序、实际版本、现有终端和配置；确认能否提供正式正文事件及额度字段。桥接先在临时配置目录安装、模拟调用及卸载，再展示个人配置增量、备份和恢复方法，获本批指令后接入。通过标准：原有 hooks、statusLine 和终端输出保留；支持正文事件时正确建立会话来源；若不支持，明确记为适配缺口或待实现，不能用额度事件当作已读取回复。不得为测试自动升级 CLI、切换认证或删除现有设置。

**T25 CLI 连续两轮和实时分段。** 在专用目录启动 CLI 学术任务；正式回复包含计划、初步结果和最终解释，第一阶段后将其他应用置前台。第二轮直接在原终端提问，无需重新接入。同时核对代码、表格、路径、文件名、Unicode 和较长正文。通过标准：正式原文及时显示；稳定阶段自动译成中文且首阶段中文早于任务结束；每阶段独立记录；第二轮自动取得；工具打印、思考状态及权限询问不冒充正式正文；正文顺序、段落和保护内容符合 T01/T02/T03。终端继续输出不被翻译等待阻塞。

**T26 CLI 断开、恢复和发送边界。** 检查从消息中途连接、停止读取再恢复、伴侣重开、终端关闭重开、测试会话切换、缺段／重放、取消和终端退回普通 shell。两会话隔离先用本机事件模拟；真实第二会话需要另列新增请求。通过标准：中途连接不伪称已取得前半段；重同步不乱拼、不重复；不会串会话或目录；退出伴侣不结束用户启动的 Claude；停止读取不等同取消 Claude 任务。现有伴随读取模式只验收翻译／复制，不能向未知终端模拟回车；自动发送须在 X02 的受控进程能力实现并通过后单独验收。

**T27 CLI 额度、配置记忆和卸载。** 检查 statusLine 实际报告的窗口、比例和 reset、缺字段、重复报告、与桌面／网页来源切换，以及接入后重开、关闭和卸载；测试安装后用户又修改配置的情形。通过标准：CLI 来源与时间明确，缺失窗口显示未知；同值输出不能刷新额度证据日期；账户范围须明确才能复用，不能把桌面账户与 CLI 身份自动视为相同；比例不能与 token 上下文占用混淆；不为获取字段发消息。关闭或卸载只撤本项目修改，保留用户后来变更、原 hooks 和 statusLine；Claude 原终端继续正常使用。不同认证方式无额度字段时明确不支持，不接 API 账单。

## 桌面真实测试的研究场景

沿用“特征选择是否造成测试误差过于乐观”这一小型学术问题，不使用真实受试者数据或工作项目。正式执行前提交最终两轮文字及目录供本批授权。

Code 第一轮要求仅在专用空目录用 Python 标准库和合成数据比较两种流程：先用全部样本选择特征后再切分，以及仅用训练样本选择特征。分计划、初步结果、最终解释三个正式回复阶段，计算规模控制在数分钟内；不安装依赖、不访问网络、不访问目录外文件。第一阶段出现后将其他应用置前台，核对后台持续读取和中文在整轮完成前出现。最终给一张含数值和明确“标准差”列义的简短表格，并在说明中引用生成文件名。

Code 第二轮从 Claude 原输入框直接发送简短英文，要求解释一个偏差来源并报告研究局限；无需重新绑定。这样两轮同时覆盖后台分段、表格术语、文件名及原窗口输入。若平台没有输出可识别阶段，记录条件未形成；额外重新生成需要新增预算与指令。

Chat 两轮及网页两轮复用“主动回忆与重复阅读的实验设计”，先从伴侣发送中文，再从原窗口直接发送英文。第二种路径不经过伴侣，因此不把直接输入的中文作为中译外测试。每次发送前核对专用会话与实际外文内容。

CLI 使用独立空目录复用相同的特征选择研究；第一轮含三阶段，第二轮简短追问偏差来源。由用户提交或在明确授权的终端目标中提交，不沿用桌面自动按回车。CLI 正文事件支持与安装方案须先通过 T24，再安排真实两轮，不能用人工粘贴已完成回复代替实时读取验收。

## 失败处理和完成标准

发现错目标、意外发送、重复发送、凭据来源错误或私人会话采集时，立即停止该测试来源并保留脱敏证据，不继续在线尝试。一般失败先补本机复现、修复和相关回归，再复测失败项及受影响流程，不重新跑全部真实场景消耗额度。

每项结果包含版本、入口、条件、步骤、实际现象、证据、请求量及通过／失败／未测／条件未形成／不适用。不同入口、翻译器和版本独立判定。模拟通过不能写进真实通过栏；重试恢复不能写成首次无失败；缺少真实测试机器不能用同机模拟替代。

正式桌面、网页与 CLI 可分别验收，CLI 读取与发送也分别给结论。硬门槛为：错会话写入、意外或重复发送、旧译文覆盖新内容、密钥送错来源及清除后记录复活均为零；上限内正式内容无静默丢弃；保护内容和表格数字一致；Code 阶段中文早于整轮结束；实际验收入口没有未解决的阻断问题。语义不足、平台限制和未测组合明确列出，不宣称全部服务或浏览器已经通过。

测试后恢复事先记录的语言、字号、发送和来源选择，保留用户密钥及登录；测试文件仅报告位置，不擅自删除。后续结果另存有日期的报告并关联本计划；既有报告和更新历史保持。
