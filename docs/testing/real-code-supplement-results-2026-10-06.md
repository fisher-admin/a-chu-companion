## 本地复现与修复

发现一种可重复的结构性原因：已完成第一个表头后，轮询更新将已翻译前缀裁掉，只重新解析剩余字符串。剩余文本不再包含完整表头及 Markdown 分隔行，后续单元格因此丢失表格身份、相邻研究语境及数字保护。即使原文没有变化，重复读取也会触发。

新增本地测试先在旧代码下失败：重复表格快照之后，后续表头不再携带统计语境。修订改为先解析完整原文，再按已翻译前缀的长度跳过片段，保留剩余片段的语境、表格标记和保护规则。已显示的中文保留，不重复请求已完成的表头。

模拟覆盖重复快照、表格后追加正文、翻译中增加数字行，以及译文中出现竖线和换行；数字、分隔符和受保护代码不成为翻译请求。该修复证明请求继续携带正确语境，**不能替代 Gemini 实际词义复测，也不代表第二阶段的在线失败已恢复**。

另一个本机复现确认：某个分段服务失败后，后续分段成功会把全局失败提示覆盖成成功提示。新增模拟先观察到该断言失败，再修订成功提示，使未处理的翻译失败继续可见。恢复后重试未完成片段，不重复请求已成功的阶段。此复现解释失败提示可能消失的机制，不据此断定第二阶段未译一定由某个特定 HTTP 状态引起。
