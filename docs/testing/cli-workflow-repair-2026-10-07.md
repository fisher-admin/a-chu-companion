# CLI连接、会话辨认及译文复制修复

日期：2026-10-07。基线为1.1.8 build67，提交`d9b8b90`；保留旧提交、应用备份、修复前失败及真实服务限制。[实施计划](../superpowers/plans/2026-10-07-cli-workflow-repair.md)。

## 已复现的问题

1. 会话绑定包含工作目录，同一个session切目录会产生额外候选；六位编号之外没有目录、模型和报告时间，难以判断来源。
2. 模型已有复制函数，但主界面没有按钮；清空草稿会清空当前输出，历史气泡也没有外文复制入口。
3. 快捷键仍先捕获普通可编辑输入框。无法捕获终端TUI或得到未知程序输入时，仅显示提示，无法继续选择CLI来源。
4. 只读等待读取状态可遮盖发出方向的翻译完成或核对提示。

修复前Python检查17项中5项失败，已保留日志。旧界面夹具实际复现快捷键无选择页、翻译后无复制按钮和清空草稿后无历史复制；协议修复前检查拒绝有效来源摘要。编译期间的字段命名冲突已修正，环境错误与行为失败不混记。

## 修订

- 仅以唯一session_id绑定来源，不以终端名字或工作目录识别。不同会话仍隔离。
- CLI底部输出与伴侣一致的编号，保留原状态栏。候选显示目录末级名、模型、报告接收时间及有无正文；报告时间不证明前台会话或服务器刷新。
- 只迁移精确匹配的旧当前目录及官方project_dir账户状态，保留旧文件；任一失效或冲突身份继续隔离。
- 有效CLI摘要可选且严格验证，不接受完整目录路径、控制字符、账户原文或额外字段；旧无摘要报文兼容。
- 非原生输入框连接动作与捕获失败均打开CLI选择页；必须明确选择，不自动绑定最新或唯一会话。已确认桌面捕获失败仍显示原错误；迟到请求不会覆盖已选择会话。
- 主界面及已完成发送记录均有「复制译文」。清空草稿可从历史复制；改草稿后不复制陈旧当前结果，未完成任务不能替换剪贴板。
- CLI输入回车执行翻译；复制后回终端⌘V粘贴并确认发送。隐藏无效自动发送控制，保留只读回复读取和对应额度自动连接。

1. 保持用户已登录的Claude Code终端，按实体Control＋Option＋E；伴侣出现选择页，选中与终端底部同编号的来源。无需重新登录。
