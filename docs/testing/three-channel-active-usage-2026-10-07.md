## 当前行为

连接 Claude 聊天后自动跟随该聊天来源取得额度，不另行要求确认额度账户。设置用于首次配置、补充获取和故障检查。

| 聊天来源 | 自动行为 | 设置中的补充功能 |
| --- | --- | --- |
| 桌面 Chat / Code | 成功绑定 Claude 输入框后读取桌面当前登录额度 | 获取桌面登录、手动 session、刷新 |
| 官方网页 | 绑定可核对的官方会话 URL，或选择已启用的网页来源后，请求该页面当前登录额度 | 获取网页额度、打开官方 Usage、Chrome/Edge 入口安装指导 |
| Claude Code CLI | 选择已经配置的 CLI 会话来源后采用该会话官方状态栏报告 | 配置入口、获取当前报告、移除并恢复原状态栏 |

桌面仍使用既有绑定快捷键。网页和 CLI 需要首次配置相应入口；打开浏览器或登录 CLI 本身不证明入口已建立。识别依据是官方内容、会话和账户证据，不按终端品牌猜测。网页现有 Chrome/Edge 配置路径；Safari没有适配器，不能宣称已支持所有浏览器。

切换来源、停止读取或身份证据失效时先隐藏旧额度。只接受当前来源与当前账户的有效报告；缺失窗口显示未知，不显示0%，不拿桌面账户替代网页或CLI账户。只有一个实际账户，本轮真实换号未验收。

网页额度查询独立于正文采集，原文读取及及时翻译不等待额度请求。官方页面使用现有会话进行同源只读查询，前后核对身份；不提取、储存或转发Cookie。组织不唯一、身份变化、请求失败或结构不支持时停止采用数据。该接口不是稳定公开API，真实兼容性待验收。

CLI“获取”触发官方状态栏重新报告已有会话信息，不发送研究问题，也不声称强制刷新服务器。官方 `rate_limits` 在Pro/Max首次API响应后才可能出现，某个窗口可能缺失；修改状态栏命令会触发重跑。参见[官方状态栏文档](https://code.claude.com/docs/en/statusline)。账户变化后旧会话不能借新全局登录恢复旧账户额度。

## 完整真实测试流程

复用已有授权，首次配置或必须亲自操作的条件集中处理；不为每条测试再次授权，不反复重启或绑定。记录同一安装版、具体会话与观察时间，不拼接旧版证据为当前通过。

共同场景：检验“全样本选特征后再交叉验证”为什么高估预测表现。Chat用概念比较；Code/CLI在隔离目录用合成数据分阶段实验，不访问个人文件。每个来源最多两轮，优先复核已有回复；失败不重复发送已完成问题。

第一轮中文：

> 请研究全样本特征筛选与嵌套交叉验证的评估偏差。用合成的纯噪声二分类数据比较：先用全样本选特征再交叉验证；以及每个训练折内部选特征再评估。分阶段说明设计、计算结果和解释，用小表格比较，保留数值与代码。先说明设计，再计算，最后给出局限；不要访问个人文件，不要联网。

第二轮中文：

> 请检查第一轮是否把模型选择与性能估计混在一起。增加完全独立的测试集，说明结果与结论的变化，用表格列出各流程仍有的风险。区分随机波动与数据泄漏。

### 桌面Chat与Code

1. 一次绑定对应输入框，立即检查额度自动选桌面来源，无需设置再连接。核对当前账户、五小时/周比例及服务提供的reset；缺失保持未知。
2. Chat执行概念版两轮；Code在空隔离目录完整两轮。核对中文转所选外语、仅发一次；仅填入模式不发送，回车与实体中文选字分别核对。
3. 每段正式原文先显、稳定后及时中文；排除工具/思考状态。Code第一阶段中文在任务结束前出现并记时；表格行列、数值、代码和否定限定语保持。
4. Claude原窗直接输入也持续读取；切到其他程序、隐藏伴侣、切换会话及停止/恢复，旧回调不恢复旧内容。
5. 历史选择、清除保留草稿、字号、头部阅读和滚动；十条上限优先已有历史，不新增十一条。设置获取只作补充刷新。

### 网页Chrome与Edge

1. 先确认无模拟脚本标记。首次配置只读入口和对应公开扩展ID，启用指定官方测试标签；其他标签原状保留。
2. 连接网页聊天来源，额度自动采用该标签当前账户，不另确认额度账户。与该账号Usage比较百分比、reset和时间；手动获取再发一次只读请求。
3. 两轮核对外语发送、原文先显、及时中文、历史、表格和后台；额度失败/等待不阻塞回复和翻译。失效登录或超时不显示旧值或假0%。
4. 会话切换、停止、刷新后核对隔离与同步；有两个实际账户再测换号，旧值立即隐藏，身份变化请求作废，新有效报告才显示。
5. Edge独立重复安装及关键流程，不能用Chrome代替。Safari目前暂不支持，后续适配另验收。

### CLI：Mac可见终端

1. 设置首次配置入口，保留原状态栏与无关设置。Mac普通shell启动全新交互式Claude Code，使用隔离目录；任一终端品牌均按实际会话来源核对。
2. 报告到达后只选对应CLI聊天来源，额度自动跟随；首次响应前或缺窗口保持未知。
3. 在可见终端执行两轮研究；正式阶段读取需具备已验证的会话能力。缺能力明确提示，不安装猜测的MessageDisplay钩子。
4. 与该会话官方状态栏比较额度、reset和身份；获取按钮的新报告不能把同一缓存标成服务器新查询。原状态栏正常输出。
5. 换终端窗口/载体、后台、结束旧会话及启动新会话；全局换号后旧报告不恢复旧账户。没有第二账户保持未完成。
6. 移除恢复原配置，再配置后新会话身份重新核对。后台命令成功不替代可见终端研究往返。
