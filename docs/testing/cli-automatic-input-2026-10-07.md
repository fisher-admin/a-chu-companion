# CLI 自动填入与发送修复记录

基线为1.1.8/build68、`04d4b05`。旧版只提供复制按钮，未完成自动输入；旧测试与版本记录保留，不将其改写成已验收。[设计](../superpowers/specs/2026-10-07-cli-automatic-input-design.md)与[计划](../superpowers/plans/2026-10-07-cli-automatic-input.md)记录本轮授权范围。

## 修复内容

- 输入目标与回复读取分开保存：CLI的正式回复到达不会清除自动填入目标。
- 不按终端品牌识别；绑定原程序、窗口、焦点/输入表面、CLI会话和20位进程绑定标记。只在当前底部提示区匹配，旧滚动历史、不同窗格、已存在草稿均不启用自动投递。
- statusLine只读上报真实Claude祖先进程的PID、启动时间和TTY；不采信消息里传入的进程值，不上报参数、完整目录、聊天正文或登录信息。每次操作时复查对应进程及前台进程组。
- 快捷键捕获后可自动匹配唯一且已核实的来源；单独选择会话只开启读取，不能凭“最新报告”启用输入。报告比屏幕重绘先到时，短暂等待页脚，不要求重新启动CLI。
- 中文翻译通过已有保真校验后，粘贴一次；短单行文本完整接收并再次核对目标后，按用户“填入后发送”偏好发送一次回车。
- 多行/表格完整填入，但不自动猜测终端Enter模式。折叠长粘贴明确标为未能核对全文，不自动回车、不重复粘贴。临时重绘在同一约2秒确认窗口等待，不把瞬间不可读当成目标退出。
- 切源、窗口/焦点变化、进程挂起/退出、PID重用、翻译取消或迟到均阻止后续自动操作，保留译文。以`!`或`/`开头的译文由用户核对，避免误切到CLI命令模式。
- 原剪贴板全部格式在本次内容未被他人替换时恢复；外部复制的新内容保持。

## 原生窗口与真实元数据补测

- 本项目独立AppKit模拟窗口实际收到 `Hello.`，并观察到回车后的提交标记；两行 `First line.` / `Second line.` 完整保留，未自动回车。
- 已有草稿再次点击填入时被阻止；长内容折叠为 `[Pasted text #1 +120 lines]` 时只粘贴一次、不回车，伴侣明确提示并保留草稿与译文。
- 模拟夹具最初有焦点保护失败：两个窗口在同一应用，夹具只恢复窗口、没有激活应用；补齐夹具激活后，以上原生测试通过。生产投递器本已调用目标应用激活，未用放宽保护来通过测试。
- 首次安装后真实CLI报告为只读，只读进程元数据检查定位为当前原生CLI的名称是 `Claude`。修复前新增检查失败；补齐Python/Swift大小写匹配后，来源4项与原桥接/额度共23项、CLI40项通过。真实前台TTY进程的PID、启动时间、TTY匹配成功；无TTY桌面进程和 `Claude Helper` 不因此获得投递能力。
- 以上不调用真实Claude/Gemini来生成测试回复。真实进程检查只读元数据，未读取参数或聊天；原生输入目标仍是本项目夹具，不能代替真实终端验收。

## 真实终端验收方案

1. 已登录的本机Claude Code保持空输入区，按实体Control+Option+E。伴侣应显示正在读取和可填入连接；底部必须出现`输入`及20位标记。新版脚本会在下一次状态栏刷新显示标记；没有标记时仍是只读。
2. 先关闭“填入后发送”，输入“请用两句话解释交叉验证。”，确认译文自动出现在同一CLI输入区；由用户检查后发送。无需重新登录或重新开辅助功能权限。
3. 回到空输入区，开启“填入后发送”，输入“请说明一个限制。”，确认短单行译文只发送一次，正式回复原文到达后及时译回中文。
4. 多行、普通Markdown表格及长文分别核对：自动粘贴保持内容和行列；折叠时不自动回车，伴侣显示明确提示；不能根据占位符判断全文接收。
5. 第二个窗口/标签/分屏：原绑定不得自动迁移。翻译中换窗、挂起或退出Claude：不得继续回车，不得把文本送到普通shell。
6. 不同终端载体分别记录版本、可读取的输入表面和结果；GPU/canvas、混合分屏、旧hook、npm/node载体或远程SSH不能被默认宣称已兼容。

桌面工具此前拒绝直接控制真实Terminal，且模拟按键不能触发Carbon全局连接快捷键。本轮不以shell或AppleScript绕过限制；真实终端最终动作由用户完成。公共GUI按键存在检查与发送之间的时间差，本方案不声称理论零竞态或全部终端兼容。
