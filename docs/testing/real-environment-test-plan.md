# A畜伴侣优化：独立真实环境测试方案

修订日期：2026-10-05。**本文件是总测试安排，不代表所有项目已通过。**桌面 Chat 三轮学术场景与历史定位已完成，当前安装为 1.1.7/build37；Gemini 出现 503 后需重试，连续可用性未通过。具体结果见 [真实学术场景记录](real-academic-chat-2026-10-05.md)。Code、网页和其余未覆盖专项保留待测。开发与模拟结果见 [实施模拟报告](optimization-implementation-report.md)，旧版证据见 [基线报告](optimization-validation.md)，设计见 [优化修订方案](../OPTIMIZATION_PLAN.zh-CN.md)。

## 本次验收范围、完成条件与时间安排

主要范围是 **Claude 桌面 Chat、桌面 Code 和 Chrome 中的 Claude 网页版**；翻译优先沿用已保存的 Gemini 配置，已安装语言包的 Apple 翻译作对照。CLI 是实验入口，只有单独选择后才测试，CLI 未测不阻止桌面和网页各自验收。其他浏览器、其他翻译服务、真实超长消息和整机重启均分开安排。

本方案的“完成”必须满足：候选版本安装与原授权连续；中文输入可正确翻译、填入并按已选择的方式发送；两轮连续回复和原窗口直接发送都能自动读取；原文先显示，稳定正式段及时自动译成中文；Code 第一段中文早于任务结束；后台、历史、滚动和清除记录不破坏已有内容；额度显示有可对照来源。桌面、网页、每个翻译器分别给结论，不用一个入口的通过替代另一个入口。

| 批次 | 内容 | 计划时间，不作为性能承诺 |
| --- | --- | --- |
| A | 版本/签名/备份、安装、连接、桌面 Chat 与发送方式 | 35–50 分钟 |
| B | 两轮 Code 稳定分段、慢翻译/切会话、历史与记录保留 | 30–45 分钟 |
| C | 所选网页入口的安装预览、两轮往返、导航与恢复、额度对照 | 25–40 分钟 |
| D | 字号/主题/输入法/设置记忆、已选翻译器对照与 30 分钟后台观察 | 45–60 分钟 |

可分两次完成；中途保存已测状态，第二次从未完成项继续。发现问题后先修复、模拟回归，再对失败用例和受影响用例复测，不连续消耗真实额度尝试未经核对的修复。

**建议首轮预算：**桌面 Chat 采用下述学术场景，共 3 条新消息；桌面 Code 新任务 2 个、网页新消息 2 条，共 7 个新请求；重新生成最多 2 次，合计不超过 9 次 Claude 生成。使用已产生的测试内容完成历史、滚动、字号、背景和多数恢复检查，不为每项重新生成。Gemini 暂设总计最多 30 次 HTTP 请求、累计送译正文最多 30,000 字符，含连接测试和分块翻译；达到任一预算即停止读取/发起新翻译，先汇报未完成项。预算是执行上限，不代表一定会用完或服务保证免费。若实际分段少于 11 条，最近 10 条保留的真实超量检查标为未完成，增加生成需另获授权。四语、50,000 字符真实翻译及正式性能重复采样使用单独预算。

测试开始前确认：所选入口、安装/重启许可、这些固定消息及命令、所选翻译器及预算、是否允许读取用户主动打开的 Usage 页。**提供本方案本身不等于收到执行授权。**

4. 真实 Claude 使用专用测试会话和一次性空测试目录；测试消息由用户发送，或在内容、目标及操作已经明确授权后执行。程序不能为取额度自动发消息。
5. 在线翻译每家单独选择。API key 在本机密码框输入，不在聊天传递；默认只做 1 条短句双向，其他模型和语言分别记录是否执行。

## 本次主场景：简单的学术研究讨论

**研究问题：大学生学习后，主动回忆是否比重复阅读更有利于一周后的记忆保持？**这是讨论研究设计，不是声称实验已经进行或结论已经成立。不使用真实受试者数据，不要求 Claude 编造文献或数据。

共三轮，每次要求 Claude 用英文回复，让伴侣自动译回中文。

**第 1 轮，从伴侣输入中文并发送：**

> 我想研究：主动回忆是否比重复阅读更有利于大学生一周后的记忆保持？计划招募60名大学生，随机分成两组，使用相同材料，每组学习20分钟，一周后进行同一测验。请用英文分三段说明研究假设、实验步骤和需要控制的因素，总计不超过300词。不要编造数据或参考文献，不要预先认定哪种方法更好。

**第 2 轮，从 Claude 原输入框直接发送：**

> 这个实验怎样减少阅读能力差异和学习时间的影响？请用英文给出两个可操作的建议，不超过150词。

**第 3 轮，再从伴侣输入中文并发送：**

> 请把上述研究整理成一个简短的操作流程，并指出两个主要局限。请用英文回复，不超过200词。研究尚未实施，不要写成已经得到验证的结论。

**本场景的验收：**中文转英文准确且只发送一次；三轮回复自动读取；原文获取后先显示，稳定内容自动译回中文；“一周、两组、20分钟、尚未实施”等含义不丢失；第二轮从原窗口发送也能被读取；最后通过“读取历史回复”选择第一轮，中文对应正确。产生三段文本本身不等于通过 Code 实时分段，后者仍按独立耗时用例验收。

网页复用前两轮，不新增研究话题。以下旧合成内容保留为专项回归备用，不再作为本次学术讨论的必发消息；若要追加，须纳入获授权的预算。

## 专项回归备用内容（保留历史安排）

**Chat 第 1 条（短句）：**

> 请用英文回复：先用一句话确认“保持原始代码，不执行任何操作”，再分三段说明一个普通文本翻译工具的使用方法，每段约 40 个英文单词。不要使用工具，不要访问文件或网络。

**Chat 第 2 条（原窗口输入）：**

> Please return three short English paragraphs labeled HISTORY-A, HISTORY-B and HISTORY-C. Include the exact inline text `--dry-run`, the path `/tmp/achu-synthetic/input.txt`, the URL `https://example.com/synthetic`, and the placeholder `{{name}}`. Do not execute tools or access the URL.

**Chat 第 3 条（段落、代码和否定词）：**

> 请用英文给出一个仅用于展示的说明，包含两个普通段落、一张三行 Markdown 表格和一个 Python 代码块。代码块必须逐字保留 `print("KEEP-UNCHANGED")`。正文说明“不要删除任何文件；完成检查后再继续”，保留行内文字 `--dry-run` 和 `{{name}}`。不要执行代码，不访问文件或网络。

**Chat 第 4 条（长回复与阅读位置）：**

> Please write an English tutorial about organizing a fictional reading list, approximately 800 words in six labeled sections. Start with LONG-START and end with LONG-END. Use only invented examples. Do not use tools, access files or browse the web.

第 1、3 条从伴侣发送，用于检查翻译和一次发送；第 2 条从 Claude 原输入框发送；第 4 条生成时切到其他程序，回来看首段中文与长文阅读。网页复用第 1、2 条。重新生成和切会话使用这两组专用测试会话，追加生成计入上述预算。

接着手动滚动到第 1 条，核对“读取历史回复”仅列当前可见完成回复；开始下一条时向上阅读，确认不抢滚动。重新生成、切会话、清除晚到结果使用这两个合成会话，不读取私人历史。

**Code 阶段测试（必须先确认一次性目录）：**

> 只使用我明确指定的一次性测试目录。先在正式回复中用英文输出 STAGE-A 和三句简短的操作计划；随后运行已经展示并获我批准的合成等待步骤，约 12 秒后在正式回复中输出 STAGE-B 和三句阶段说明，再等约 24 秒，最后输出 STAGE-C 和三句结果。不要访问该目录外文件，不访问网络，不执行安装或删除，不改任何真实项目。每阶段说明要作为正式正文，而不是工具进度或思考内容。

一次性目录在授权后才创建，建议位于项目忽略的 `output/real-tests/claude-stage-执行时间/`。创建前核对该目录尚不存在，目录内仅放合成文件，不把仓库根目录提供给 Claude Code。第一个任务两次分别执行下列命令，中间必须输出正式 STAGE-B 正文；命令只有等待和打印，不访问文件或网络：

```sh
python3 -c 'import time; print("WAIT-12-START", flush=True); time.sleep(12); print("WAIT-12-END", flush=True)'
python3 -c 'import time; print("WAIT-24-START", flush=True); time.sleep(24); print("WAIT-24-END", flush=True)'
```

**Code 第 2 个任务（较长停顿、连续读取）：**复用三个正式段落要求，标记改为 PAUSE-A/B/C，两次等待分别为 60 秒和 12 秒，仍在同一个一次性目录中执行：

```sh
python3 -c 'import time; print("WAIT-60-START", flush=True); time.sleep(60); print("WAIT-60-END", flush=True)'
python3 -c 'import time; print("WAIT-12-START", flush=True); time.sleep(12); print("WAIT-12-END", flush=True)'
```

实际命令、目录和测试内容须包含在 R1 授权范围内。等待时分别测试后台工作、停止/恢复读取；两次等待之间的说明必须是正式正文，不能把工具打印当作阶段正文。36/72 秒仅为测试安排，真实 Claude 不一定严格按该时间运行；记录真实稳定、提交、中文出现与工具任务结束的时间，第一阶段中文晚于整轮结束视为未通过。Claude 未按要求产生可识别阶段时记录“测试条件未形成”，不能把它改判通过。

**在线翻译固定短句：**

> 请保留原始代码，先检查第一步，不要删除任何文件。

> Keep the original code. Check the first step before continuing. Do not delete any files.

只使用已选服务与模型，不在聊天传 key，不为测试自动换供应商。全四语及 50,000 字符真实发送不包含在最小测试预算内。

## 1. 桌面 Chat 与 Code

| ID | 操作 | 通过标准 |
| --- | --- | --- |
| D-01 | 专用 Chat 会话连接，用户从伴侣提交短句，连续两轮；另测含明显稳定段的较长回复 | 目标正确，英文仅一次填入/发送；原文读取后先显示，稳定段自动译出，无须点击翻译或等整轮结束；进行中的预览不误标最终完成；两轮不重连 |
| D-02 | 专用 Code 任务先说明计划、执行耗时步骤、再说明结果 | 第一段正式原文先出现；稳定后自动提交翻译，第一段中文须在任务仍进行时出现，不能仅以原文及时显示判通过；记录稳定、提交、中文可见与整轮结束时间；工具状态不混入正文 |
| D-03 | Code 进行中停顿 30–60 秒再继续 | 读取不断开，暂停期间稳定正式段已有中文；不把停顿标整轮完成；后续正式段独立译出，已有中文保留，续写原位更新 |
| D-04 | 两段 Code 说明及一段含代码的最终回复 | 分段单独记录；内部翻译切片不多计历史；首尾与代码完整 |
| D-05 | 翻译慢时修改/重新生成末尾，随后切到另一个测试会话 | 旧译文不覆盖新版本/新会话；已有中文不被整条清空；发送仍需正确目标 |
| D-06 | 在真实 Claude 原窗口直接输入下一条消息 | 伴侣持续读取；无需手动历史按钮；额度刷新遵守冷却 |
| D-07 | 查阅可见历史回复，选择指定条目 | 只列可见完整正式回复，中文对应所选项；不会采入侧栏或工具输出 |
| D-08 | 关闭自动发送只填入；开启后分别用回车/⌘回车；一次快速重复提交；目标失效时提交 | 填入模式不发送；只在目标软件实际支持的发送键下验收自动发送，消息只出现一次；重复点击不重复请求/发送；失效目标明确提示且草稿保留 |

Code 测试建议使用一次性测试目录，只让任务输出阶段标记并读取该目录内合成文件。任何运行步骤都应先确认其工作目录与命令；不使用跳过权限的启动参数，不在用户真实仓库生成测试修改。

5 小时/周窗口是否存在，以当前账户官方页面的实际显示为准，不凭 Pro/Max 名称假定某窗口必然存在或不存在。对照账户类型、窗口名称、百分比和 reset 时区；缺失窗口显示未知/不可用，不能用 0% 补齐。每次回复后允许触发刷新检查，但冷却内不应重复请求；重复旧样本不能被标成刚取得的新数据。

仅桌面/网页用户不要求安装 CLI。本轮不测试 API 账单、gateway 金额或管理 key。若桌面 AX 和网页路径均未实际通过，额度来源迁移不得标为正式可用。

## 7. 性能、请求量与通过判定

时间点分别记录：源内容已暴露、采集收到、原文可见、段落稳定、翻译排队/发出、首段中文可见、整轮确认。模拟时钟只证明规则，不作为真实耗时。

分开报告“读取到原文可见”“稳定到请求发出”“请求发出到中文可见”和“中文出现时整轮是否仍在进行”。正常队列下稳定片段立即调度；忙队列、限流和失败单列原因及等待时间。第一段中文在整轮结束后才出现的分段测试不能通过，不能用低原文延迟代替中文及时性。在线服务耗时实测，不承诺固定零等待；若首段未在设计的长任务期间出现，先判断来源、队列或翻译延迟并修复/复测。

首轮目标沿用方案作测量基准：活动网页/CLI 原文 P95≤500ms，受支持前台桌面 AX 原文 P95≤1s，已预热 Apple 的短段中文尝试 P95≤2s。云端单独报告首段/完整结果、错误率与排队时间，不承诺最快或无限免费。

**计时口径：**原文延迟从来源已经向采集入口暴露可读正文开始；译文耗时从稳定段已被判定、可以发出翻译开始。当前稳定判定通常需要约 3 秒的内容不变，正文明确完成可提前提交，因此 Apple 的 2 秒目标不包含这段稳定确认时间。Code 核心验收同时必须满足“第一段中文先于整轮完成”，不能靠重新定义起点绕过这个要求。被隐藏/最小化后来源本身不再暴露内容时，单列平台限制及恢复耗时。

每组合建议至少 30 次有效采样才报告分位数，并注明样本规模；更少时列原始观测，不宣称稳定 P95。报告应包含失败/超时，不只挑成功结果。另做 30 分钟切换、长文与重连观察；更长期试用单列。

同时记录整次 AX 耗时、队列峰值、CPU/内存变化、翻译请求数和额度请求数。只有预览已独立后测出某一环节仍是主要瓶颈，才启用对应 SSE/AXObserver 优化，并与旧策略同条件对照。

硬门槛：错会话写入、旧版本冒充新译文、意外/重复发送、凭据发给错误来源、清除后旧记录复活均为 0；保护段恢复一致；正常完整内容无静默丢弃。任何一项失败先修复和复测，不进入发布。

## 失败处理、恢复和用户配合

1. **发现错误：**先停止自动发送/读取，保留不含凭据的合成截图和时间；记录失败入口、阶段、复现步骤。不得为了恢复连接重置 TCC、删除登录或重新下载全部语言包。
2. **安装或授权回归：**退出候选程序，恢复 R0 备份的 1.1.6/build33 app；验证原签名和启动。偏好仅在候选确实修改了设置且用户希望恢复时，从备份恢复；不覆盖用户在测试期间有意作的新设置，不导出或删除钥匙串内容。
3. **网页/CLI 回归：**关闭测试标签的采集；按安装记录撤销本项目新增配置，保留其他扩展/hooks/statusLine 和安装后用户另改的设置。CLI 未安装则不碰 CLI 配置。
4. **修复后：**先运行受影响模拟测试，通过后再复测失败项、发送/会话隔离和相关恢复项。增加真实消息或超出预算时先给出新增测试内容与数量，等待授权。
5. **结束时：**停止测试来源，恢复测试前语言、字号和发送选择，保留测试结果与版本历史；一次性目录只报告路径和用途，删除另经授权。是否保留候选作日常使用，由最终结果和用户选择决定。

用户通常只需完成：解锁屏幕、首次在指定输入框用实体键盘按 Control + Option + E、登录并主动打开选定 Usage 页；中文输入法选字用实体键盘配合。控制工具无法触发系统全局快捷键时，明确说明本次需要绑定哪个窗口；连接成功后同一程序的连续两轮不应反复要求绑定。安装重启后必要的重新绑定和重新授权分开记录。

需要用户确认连接时，提供可点击的“已连接”选项，由用户点击确认，不再要求手动输入该文字。随后核对伴侣实际连接状态；点击确认本身不代替状态验证。已经连接且无需重新绑定时，不重复弹出确认。

最终交付：各入口通过/失败/未测列表，失败原因与已完成复测，合成证据、阶段时间线、实际请求量、平台限制、恢复情况，以及是否适合作为日常版本的结论。**未测项目始终保留未测标记；模拟结果不能填入真实通过栏。**
