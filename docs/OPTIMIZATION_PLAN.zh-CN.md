## 1. 建议采用的路线

建议保留已有 Tracker、队列、原生 Gemini、发送校验和 macOS 界面，先补“独立原文预览＋阶段性自动翻译＋任务版本＋原位置更新”。原文及时可见与阶段性中文及时可读是首批同时验收的目标。解决这条已确认的瓶颈，再以实测决定 AXObserver 和翻译流式协议的投入。

| 路线 | 收益 | 代价与结论 |
| --- | --- | --- |
| 最小分层改进，逐批验证 | 能直接改善原文等待、重译和阅读，复用现有保护 | 推荐；先建立可回放契约，后接新来源 |
| 一次建立完整三端 Store/actor/流式架构 | 后续多来源扩展可能更整齐 | 当前多数来源尚未接入，身份与字段未经实测；一次改动面过大 |
| 只把三秒改得更短、轮询更频繁 | 局部候选可能更早出现 | 不能解决翻译队列阻挡原文、中文清空和滚动问题，还可能增加采集与云请求 |

开发批次、真实验收与安装发布分别记录。保留原有未提交文件、版本历史和签名身份，不用线上 1.1.4 替换本机。

## 2. 对原方案的关键修订

1. **纠正版本事实。**本机已有原生 Gemini、独立 Gemini 密钥、设置页和双向连接测试。Code 正式段稳定三秒即可翻译；“最新段始终等整轮结束”已不是当前事实。
2. **区分采集独立、原文展示与翻译调度。**采集已有独立任务；原文仍在 `translate` 开始时发布，忙队列中的新原文因此可能等待。先让原文独立显示，并在每个正式片段稳定时自动调度翻译；不能只解除原文等待，却把中文继续留到整轮结束。
3. **把三种结束分开。**“片段可翻译”“单条消息结束”“整轮任务结束”是不同状态。现有 Code 稳定候选不能成为完成提示的依据。
4. **保留已译内容，但明确其版本。**源段修订时，只失效受影响的切片；必要时保留旧中文并标“待更新”，不能把它当作新版本译文。
5. **先补接口来源绑定再增加预设。**Gemini 与兼容服务已隔离；自定义兼容地址改变仍能复用旧 key，这是新增 OpenAI/Grok 配置前需要解决的缺口。
6. **额度迁移有上线门槛。**先建立对当前用户可用的新来源，再实际验收和切换。不能提前取消卡片，也不能把旧凭据读取藏在新来源的自动回退里。
7. **尊重既有界面选择。**保留 610 宽窗口、顶部额度条与三个相邻操作、单排底部、默认 14 及 12/16 选择。详情折叠，不把主窗重新铺成宽仪表盘。
8. **缩减首轮范围。**不接 API 账单/管理凭据，不部署没有维护人的政策服务器，不一次接 Azure、DeepL、多个浏览器和托管 CLI。保留这些可选扩展的接口位置。

## 4. 先明确最小状态契约

首轮给现有候选增加来源/绑定代次、稳定逻辑 ID、单调原文 revision 和采集顺序；继续复用 session/attempt 失效保护。不要为了未来字段立即改写所有模块。

后续三端共同事件才逐步加入 `turnID`、`messageID`、`blockID`、`sequence`、`kind` 与证据强度。不能取得的源标识保持未知或仅在当前绑定内生成，不按文字相同跨端合并。

快照表达“此时看到的完整状态”，增量表达“上一版本后的新增内容”。缺序、来源重启、导航或分支无法确认时，先重同步快照，不能直接追加猜测。

### 原文预览与翻译

- 先创建或更新原文记录，同时进入自动翻译流程，避免快速结果先于记录建立。流动中的尾部可短暂标“等待片段稳定”，稳定后立即排队；用户不需要点击额外的翻译按钮。
- 新原文无需等待上一条云翻译；预览同样检查 session、绑定与清除代次。每个稳定片段独立成为翻译任务，不把多个阶段攒到整轮结束才翻译。
- 正式 Code 分段仍单独显示；内部句段切片不新增气泡。
- 翻译任务捕获来源 revision、语言、provider/profile 与配置版本。旧结果不得写回；新版本不能因取消旧版本而丢失调度。
- 草稿预览不挤掉十条完成译文。同一逻辑段首次成功才计入一次；后续修订原位替换，不再次计数或排序到最后。
- 清除和淘汰建立失效标记，晚到结果不能复活记录。跨绑定代次不复用身份；段落重切无法确认关联时使受影响后缀失效。

### 阶段性翻译的触发与回传

流程为：**读取正式原文 → 立即显示并跟踪稳定片段 → 片段可译时立即调度 → 该片段中文完成就显示 → 持续处理后续片段 → 消息/整轮结束时核对最后尾部。**任一步都不能要求先收到整轮结束信号。

明确的片段结束证据可直接触发翻译；没有这种证据时，首版沿用三秒稳定判断，确认的是可译片段，并非消息或整轮完成。满足条件后不再额外等待一个稳定周期或下一次工具边界。三秒是待真实测量后调整的确认参数，不是翻译服务响应时间承诺。

Chat 同样提供明确标注的阶段性中文预览；仍保留当前严格的消息完成判断，预览不会把进行中的回复误标成“已完成”。Code 的系统运行状态、按钮和工具进度不作为正式正文翻译；正式说明中的计划、分析与阶段性结果应及时处理。

对较长的阶段，按稳定正文切片提交，不等待该阶段达到全部长度上限。首版可复用约 3,000 字符的翻译块，每块完成即回传中文，而不是在整段所有块完成后一次返回。内部切片仍归属原来的逻辑回复/Code 分段，不额外创建历史条目；不依赖服务商提供流式接口。

后续原文继续到来时保留已完成中文，仅翻译新增或被修订的部分。最后的消息结束事件用于补译未稳定的正文尾部、核对完整性与更新状态，不触发已译内容的重复整条翻译。清除、切会话或停止读取后的旧片段仍按失效保护处理。

### 队列与结构保护

维持首轮串行翻译，但以稳定切片为调度单位，每个切片完成后允许其他就绪片段获得执行机会，避免前一条长回复的全部翻译阻挡后续阶段。仅合并同一逻辑段、同一切片的旧版本任务，不把其他未译的稳定切片一起丢弃；增加任务数与待译字符双重预算。没有在途请求、服务端限流或失败退避时，就绪片段在下一次调度立即开始；不设“整轮结束后才放行”的批量门槛。

饱和时明确显示“排队翻译”，保留当前原文并给稳定内容恢复调度；不能静默丢掉最后一段、使快速变化的一条长期阻塞其他片段，或一直停在只有原文的状态。翻译失败应显示原因与重试入口，不能将其记为已译。健康/额度刷新冷却只适用于检查和用量请求，不延迟正文翻译；实际翻译服务限流另行遵守。

以提取到的原文为基准识别代码块、行内代码、URL、明确路径/命令参数和占位符。自然语言段翻译后把保护段按结构恢复，验证相同；不以正则把全部英文都判成代码。围栏未闭合时暂时保护剩余代码，待结构完整再判断。解析或恢复无法确认时保留该段原文并提示，不把可能改坏的代码作为已验证译文。

## 5. UI：同时保留“从头读”和“不抢滚动”

为新回复首次显示、同条修订和用户主动回顶设置不同阅读意图。新回复默认从头读；若用户已开始滚动/选字，其操作优先。同条增量只更新原位置，额度或自检变化不发滚动命令。

先改现有 `LongMessageReader` 的更新契约，保留长文可选择和复制。首轮不同时删除内层阅读器并更换整个时间线；单滚动或独立阅读窗作为后续验证项。

主窗保持来源、阅读、输入三个核心区。顶部进度条仍直观看额度，展开查看来源、数据年龄和连接方式。右上刷新、额度连接、翻译设置继续相邻。关键状态用文字解释，正常自检静默，不为未使用服务弹错。

输入区可在最大显示高度内增长；底部保持一个明确主动作和一行辅助入口。“翻译并发送”只在既有自动发送开启时显示，升级不改变开关。12/14/16 与磨砂主题保留，较小辅助文字按实际布局提高可读性。

## 6. 自检：先可用，再检查

每次窗口显示更新权限、已启用来源和配置状态；进程启动/唤醒合并检查。同一检查键只运行一个任务，配置改变只让相关缓存失效。

| 检查 | 首版动作 | 不做的推断 |
| --- | --- | --- |
| 权限与当前来源 | 使用现有权限监控，检查已绑定来源可读性 | 未安装 CLI 不使桌面翻译失效 |
| Apple 语言 | 区分已安装、待准备和不支持 | 不在自检静默下载语言包 |
| 云翻译配置 | 验证模型/地址/密钥配置状态；读取缓存 | 配置存在不等于模型实测成功或有免费余额 |
| 实际翻译连通性 | 保留用户主动点击固定短句测试 | 不每次打开自动生成文字 |
| Claude 用量 | 读取已连接来源与带时间缓存 | 没新证据不写 0%，不为额度发聊天 |
| 兼容/免费政策 | 内置核验日期与官方链接 | 不调用大模型判断价格、不自动更换模型 |

远程只读检查仅针对已启用且有适用接口的服务；首版不为所有供应商添加管理权限。未知/离线/不支持/未配置/旧数据分别呈现。

首轮成功冷却可从 60 秒开始、失败指数退避并尊重服务端等待信息；手动刷新可越过成功冷却，但仍遵守明确服务端限流。数值是待验证参数，不是官方保证。账号或来源变化取消旧请求，不能把旧值继承到新账号。

政策记录先内置。未来只有在维护、签名密钥轮换、发布与回退职责明确后，才做签名远程清单；只更新声明性事实，不远程下发执行代码。

## 7. Claude 用量来源与迁移

对当前以桌面为主的使用方式，先验证**用户可见的桌面 Usage AX**；如果该版本不暴露字段，提供**官方网页 Usage 的独立页面读取**。已有 CLI 的用户可选官方 statusLine，不要求为了额度强装 CLI。

官方 statusLine 提供适用账号的五小时/七天比例与 reset 字段，字段可能独立缺失，且通常在正常会话首个响应后出现。它是客户端报告来源，不能通过反复运行脚本宣称查询到服务端新余额。[官方 statusLine 文档](https://code.claude.com/docs/en/statusline)

套餐名称只作账户描述，窗口以实际字段为准；不要硬编码“Max 一定没有五小时窗口”。收到新数据的时间与额度证据的时间分开，重复相同输出只证明桥接在线。

### 新来源的最小模型

保留 `usedPercentage?`、`resetsAt?`，补来源类型、账号绑定、窗口语义、证据时间、接收时间和新鲜度。没有明确账号证据时让用户选择/确认关联，不把 CLI session ID 自动当账号 ID。同账号同窗口比较时间与来源，冲突提示，不相加百分比。

重置时间到达显示“等待新值”，不自动补满。若增加跨重启缓存，只保存明确选择的额度快照和最少来源标记，不保存聊天、Cookie 或密钥；首轮不默认改变现有运行内记录政策。

### 切换的顺序与门槛

1. 在开发/模拟中加入新来源与连接界面，现有卡片保留。本轮不改正式程序的额度连接。
2. 新来源至少在用户实际用的入口取得一条可核对真实样本，缺失、过期和账号隔离通过验收。
3. 做切换预览：显示新来源和适用窗口，告知以后不再自动提取旧来源凭据；用户执行或明确选择切换。
4. 原子保存新来源选择并关闭旧来源自动回退。不能新来源失败就悄悄恢复 Cookie 路径。
5. 没有可用替代来源时，保留旧值时间/“连接来源”入口，明确该机器迁移未完成；此项是正式迁移发布的阻塞条件，不以删卡片通过。
6. 清理只针对伴侣自己保存的旧 session，作为单独可审查操作，不动 Claude 登录。旧来源退出在迁移发布说明中设定，不能永久隐形保留。

替代采集不抢聊天焦点、不导航当前会话、不读取 CLI OAuth 文件。网页专用用量页只有用户启用后才维护；仅桌面无法持续暴露 Usage 时，应诚实说明页面来源的更新条件。

## 8. 三端适配与服务商扩展

### 桌面

先设正文采集的整体预算、单次任务合并和采集耗时计数，再考虑事件唤醒。同步 AX 调用不能仅靠 Task.cancel 得到硬超时；必须限制单元素等待、遍历工作量，保留最后有效快照。AXObserver 是唤醒手段，通知不支持时继续轮询。[Apple AXObserver 接口](https://developer.apple.com/documentation/applicationservices/1462089-axobserveraddnotification)

### CLI

先做已有交互终端的回复旁路读取：`MessageDisplay` 批次转交后立即返回，不在 hook 中等翻译；处理索引、空 final、重复与缺批。该 hook 的非交互模式不能作为同等实时流，需按当前安装版本检测。[官方 hooks 文档](https://code.claude.com/docs/en/hooks)

任意已有终端首版提供翻译/复制，不模拟回车。伴侣拥有的官方进程才后续评估受控输入、会话续接和取消；使用参数数组与管道解析 `stream-json`，只取消自己拥有的进程。[官方程序化输出文档](https://code.claude.com/docs/en/headless)

### Chrome

先分出最小 Native Messaging 传输与 Usage 页面模块，避免额度迁移被“完整网页聊天扩展”拖住。正文采集后续共用来源事件。校验扩展身份、来源域名、字节长度、大小及 schema；页面不能发读取密钥/改配置/发送消息等高权限指令。实现导航代次、序列缺口、重同步和后台休眠状态。[Chrome Native Messaging](https://developer.chrome.com/docs/extensions/develop/concepts/native-messaging)

### 翻译服务

Apple、现有兼容接口与原生 Gemini 优先。先建立来源绑定，再提供 OpenAI/Grok 预设；Grok 能复用兼容传输，但有独立配置和契约测试。预设只建议地址/模型，不替换用户已验证的 Gemini 模型。没有 key 的预设保持未配置。

## 10. 首轮模拟新增要求与完成定义

现有 215/14/5 项是基线。后续至少新增：

- 可阻塞的假翻译器加虚拟时钟：原文先显示且自动进入翻译；第一阶段中文在后续阶段和整轮结束前出现，译文乱序不回填；固定随机种子复放有同一最终状态。
- 分阶段时间线：0 秒获取 A 段，3 秒稳定并立即提交，假翻译 0.2 秒后显示中文；B 段 12 秒后才出现、整轮 36 秒才结束。必须断言 A 段中文约 3.2 秒可见；这些是模拟安排与预期，尚未执行，不代表真机耗时。
- 长段逐块完成时立即回传；繁忙翻译器不阻挡原文，前一条长回复的块间可调度新稳定段；没有限流时不附加健康/额度冷却。
- Chat/Code 的阶段性译文预览与最终完成标志分别断言；正式正文有中文，运行提示不混入；最终事件只补尾部，不重译已完成片段。
- 十条已完成记录与临时预览分离：第十一条淘汰、同段多次修订、清除期间返回、段落重新切分。
- 队列任务数/字符预算、优先稳定最终内容、无饥饿与延期恢复。
- profile 来源规范化、已保存 key 的迁移/回滚；新域名无隐式认证。
- 只改消息尾部不清空前面切片；代码围栏跨批次、错误标记和安全恢复。
- 自检单飞、冷却、限流、旧值状态，以及用量来源迁移中断/重放/冲突。
