# 三种额度来源与当前账户识别

本轮根据用户已确认的继续测试、载体无关、三入口和账户切换要求修订。保留全部历史记录和既有设置，不自动提交或发布。

## 行为

连接面板分为 Claude 桌面端、Claude 网页端、Claude Code CLI。选择入口仅筛选候选来源，不中断现有连接；确认连接才切换。CLI 使用 Claude Code 官方事件和 statusLine，不识别终端品牌。网页以官方 claude.ai 内容为依据；浏览器接入能力须分别验收，不能把 Chrome 测试称为 Safari 已支持。

额度必须属于已核对的来源、会话和账户。人工备注不能证明账户身份。身份缺失、账户变化或来源重启时先清空旧额度，显示核对状态；旧账户延迟报告不能恢复。无数据表示未知，不表示 0%。旧版本可见来源配置保留，但首次恢复须重新核对身份。

桌面凭据在请求前后核对。可见来源采用只含账户指纹、遮蔽显示名称、来源代次及单调序号的身份报告，不转发邮箱、登录密钥、Cookie 或 OAuth。账户指纹只用于本机比较，不进入公开文档或日志。

CLI 在 SessionStart 时核对官方 auth status，将身份绑定到这一会话；后续报告再核对。配置账户变化后旧会话失效，必须由新 Claude Code 会话重新绑定，不能用全局新登录给旧进程的缓存额度改名。未安装 SessionStart 的旧会话继续读取正文，但额度身份标为待核对。

网页只有在当前 DOM 明确包含唯一账户邮箱、且同次读取前后身份一致时才发布可信额度。仅昵称、套餐和组织名称不能证明当前账户。身份不可见时发送待核对事件，立即清空已连接的旧额度。网页自动后台取得身份及不同浏览器安装属于真实验收项目，当前不能以手工浏览器读取替代程序自动成功。

## 测试与完成条件

模拟覆盖三入口过滤、不混合不同来源、A→B→迟到 A、身份缺失、代次切换、乱序、重启旧配置、无额度字段、当前 Usage 新布局及原状态栏卸载恢复。全套既有回归通过、可编译后才形成候选安装包。

真实测试不自动切换个人账户。已有可见 CLI 研究测试仍等待首次问题提交，最多一条问题、零 Gemini 调用。Web 先只读官方账户菜单和 Usage。真正的双账户切换验收需要两个用户可用账户并由用户完成登录；模拟结果不算真实切换成功。最终报告分别标明代码验证、页面只读观察、程序往返验收。
