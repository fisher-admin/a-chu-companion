# build78：无浏览器组件的网页额度读取

用户已明确批准改为伴侣直接识别Claude网页Usage。build77油猴方案撤回，保留其提交、模拟结果与未通过真实额度的记录。网页额度不读取Cookie、钥匙串、浏览器私有设置，也不把桌面账户或伴侣内独立登录冒充网页账户。

## 正常使用

手动连接Claude网页输入时，另存同一应用和精确窗口作为额度读取范围，独立于发送租约。前台首次连接和显式刷新执行：当前账户菜单唯一邮箱 → 同窗Usage → 账户菜单再次核对 → 恢复原页面。仅前后账户一致、窗口未变、官方页面和明确的订阅用量分区存在时发布。邮箱仅短暂处理，界面与偏好只保留遮蔽标签及哈希。

设置提供“读取连接窗口额度”和“读取已打开Usage”。后一入口没有聊天目标时，仅接受唯一的正式Usage窗口；多候选不取第一个，提示用户先连接所需窗口。这个补充入口不创建、替换或重选消息输入目标。

现有Usage若是其他设置子页不自动改动。非Usage聊天页面的恢复须回到原会话URL并保留已选输入；失败停止进一步自动操作并报告，不重新选择输入。退出、重新连接、窗口消失、失去身份和前后账户不一致先隐藏旧值。

## 数据及后台边界

解析英文、简体与繁体，支持“34% used”“已使用34%”“34%已使用”。优先读对应分区的AXLevelIndicator；同分区文本与控件矛盾则拒绝。付费额度、各产品分配和模型专属额度不混入总周限额。保留网页实际重置描述，不凭猜测转成精确日期。

自动请求仅在原浏览器窗口已在前台、伴侣没有发送任务时运行，不激活后台浏览器；失去前台立即取消进一步页面操作。显式按钮允许一次恢复所选窗口。后台只给出“需刷新／最近核验”状态，不能把没有账户证明的候选值发布为实时数据。后台是否可无干扰自动刷新另行实测，不预先宣称成功。

## 验收

测试先失败再修复，覆盖本地化、分区、零与缺失、冲突数值、邮箱唯一性、账号往返变化、精确窗口、取消与旧请求、后台不激活、恢复失败及不调用发送。完整旧套件继续通过。原签名安装，确认包内没有浏览器安装组件、原文读取和发送路径保持。真实验收只读当前网页额度与账户，不发送Claude问题、不退出或切换用户账户。
