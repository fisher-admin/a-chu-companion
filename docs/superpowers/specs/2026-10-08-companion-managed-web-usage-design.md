# 伴侣管理的网页额度连接

用户在 2026-10-08 明确修订接入要求：由伴侣准备、加载和管理必要接口，用户仅参与必要登录或授权，不再在 Chrome 配置开发者模式、加载目录或复制扩展 ID。沿用用户已经授权的修复与测试范围执行普通设计和代码工作；浏览器安装授权仍由用户完成。

## 选择与范围

本机采用已经安装的 Tampermonkey 运行最小额度模块。伴侣打包模块、提供仅本机安装地址、打开正常安装授权并管理配对。只在运行组件已获准执行脚本时可用；没有心跳时不得宣称成功，更不能修改 Chrome 私有设置。正式分发仍推荐官方商店扩展和固定 ID 自动登记，目前未发布商店版本。内置 WebKit 独立登录不等于外部浏览器当前账户，因此不用于冒充当前账户。

额度模块仅在 https://claude.ai/ 顶层页面运行，读取当前页面凭据对应的账户及组织额度；不使用 Cookie API，不转发 Cookie、完整邮箱或聊天正文。AX 回复读取、翻译和用户手选输入位置保持独立。

## 连接、授权和身份

伴侣内按钮准备五分钟、一次性安装能力；模块在隔离存储中生成长期安装身份和密钥。密钥不出现在安装 URL 或源文件中。持久授权保存在伴侣私有文件和脚本管理器隔离存储，重启、同身份升级继续使用。

正常输入连接仍由用户指定输入区。热键捕获网页时，在抢走浏览器焦点前发出短时随机挑战，等待唯一聚焦、可见页面响应；最多延迟面板 1.5 秒。无响应或多个响应时正常打开面板，只将额度置为未连接，不能按相同 URL 猜标签页。授权后的稳定绑定是安装实例加标签实例；页面刷新产生新的 documentID，应用重启产生新 epoch；这些均不声称是 Chrome Profile 身份。

安装后如已有目标，可在伴侣点击“连接已指定网页”：程序返回此前由用户选择的浏览器窗口与输入区，再执行同样的焦点挑战。它不能自行选择其他窗口，也不向输入框写入文字。

## 获取和失效

取得账户、额度、再次取得账户，前后身份和组织一致才发布。输出仅包含遮蔽名称、账户指纹、两种额度百分比与重置时间。退出、读取失败、账户变化或心跳失联先撤回旧额度；新账户稳定后再显示。绑定标签导航继续跟随，其他标签不能接管。收到 Claude 正式回复时请求更新；并保留设置中的补充刷新。

## 本机传输

随附 Python 标准库服务只监听 127.0.0.1。伴侣监督子进程，通过私有管道传递控制和事件。端口及授权文件为用户私有，不写入公开仓库。服务校验 Host、请求大小、JSON 字段、认证签名、应用 epoch、递增序列及一次性挑战；没有 CORS 或 Cookie。安装能力短时且单次消费，未知网页不能通过表单或盲 POST 配对。应用退出关闭服务；撤销连接移除授权并清空网页额度，不影响其他端。

## 验收标准

- 设置中不再要求选择扩展文件夹、输入扩展 ID、配置 native host。
- 实际网络模拟覆盖授权、焦点挑战、多相同地址标签拒绝歧义、账户更换、过期能力、签名与序列重放、错误 Host、跨站 Origin、超大或含秘密字段的请求、重启复用授权和失联撤回。
- 模块模拟验证隔离密钥、同源读取、前后账户复核、定时与主动刷新、无正文/Cookie上报。
- 原有 39 组回归及编译安装通过；保留固定签名和修改历史。
- 真实额度测试不向 Claude 发消息。用户只处理不可代为确认的正常安装授权；取得真实心跳和当前账户额度前不报告网页额度成功。

依据：Chrome 官方外部安装文档、Tampermonkey 安装及 GM 接口文档，2026-10-08 核对。普通 macOS 外部扩展安装需商店发布，不以本地 CRX、企业策略或被禁止的浏览器内部页面绕过。
