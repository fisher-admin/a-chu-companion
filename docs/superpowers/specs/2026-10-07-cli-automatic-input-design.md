# CLI 自动输入设计（build69）

用户已授权按照“绑定具体终端输入位置、翻译后核对并自动填入、按设置发送”的方案修复。基线为 build68 / `04d4b05`，不改写旧提交或旧测试结论。

## 完成条件

- 实体连接快捷键保留终端窗口和输入表面；未知载体按内容识别，不按程序品牌识别。
- 本机只读桥接报告附带从真实 Claude 父进程导出的输入标识；不采信消息中的 pid，不传递命令参数、账户原文、完整目录或聊天内容到日志。
- GUI 当前输入表面的底部标记与报告匹配，且进程仍为对应终端的前台任务，才建立可填入连接。仅选择一个历史来源不能启用发送。
- 翻译任务冻结连接、会话、草稿和发送偏好；任务期间切换来源、窗口、标签、分屏，退出/挂起 Claude 或修改输入均不迁移发送。
- 正文/额度到达不会抹掉已验证的 CLI 输入目标。仅停止读取保留输入绑定；停止桥接或切换原生来源撤销 CLI 绑定。
- 完整译文通过现有保真检查后，通过 macOS 剪贴板和键盘事件填入原输入区。粘贴前后重新检查当前目标，保留剪贴板所有格式并避免覆盖用户新复制内容。
- 自动回车只在可确认译文已进入输入区时执行。折叠长粘贴不能凭占位符声称内容完整；无法核对时不自动回车、不重复粘贴，提示用户检查，保留完整译文和复制入口。
- 表格、多行与 10,000 字符输入规则保持；远程失败后的系统兜底仍须人工核对，不自动送出。

## 边界与选择

采用独立 CLI 投递路径，复用原生剪贴板行为；不复用桌面编辑器“整个 AXValue 等于草稿”的规则。附加只读进程来源，不通过桥接发送命令，也不向 /dev/tty 写入来伪装键盘。

PTY 包装器会要求用户重新启动原有会话；逐品牌脚本无法满足载体独立，两者不作为本轮默认实现。无法提供可核对输入表面的终端、远程 SSH 或混合多分屏仍可只读/复制，并明确提示边界。

## 验证

先保存修复前失败，再测试来源解析、GUI 内容解析、多个会话与窗口隔离、翻译晚结果、原文读取保持绑定、剪贴板归还和取消。通过独立 AppKit 模拟输入表面实际核对自动粘贴与发送键，再执行全量 Swift、Python、socket、HTTP 和资源/签名检查。

真实 Terminal 的操作受桌面工具限制，不能用 shell/AppleScript 绕过。模拟通过单独记录；最终真实终端操作由用户完成，不能宣称全终端兼容或真实往返已验收。
