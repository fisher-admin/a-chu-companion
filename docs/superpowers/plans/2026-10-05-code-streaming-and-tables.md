# Code 实测修订：流式身份与表格

用户已授权优化、模拟回归及本批两个 Code 真实任务，并在测试中强调保持表格。修订沿用原文先显示、稳定正文及时回译、工具状态不进入正文、最近十条记录的既有要求。保留 build37 和全部先前证据。

## 实测原因

Claude 桌面 2.19675.0 的活动回复显示为 `Currently streaming message` 容器，结束后在可见辅助功能树中显示 `Message 2`。可见描述不排除隐藏 title 已含编号，因此修订同时接受可核对的隐藏编号。第一任务实测中，旧读取未及时发布早期正式阶段；修订明确流式容器的作者与边界，避免把它混入上一条用户消息。期间还出现流式容器尾部的 token/running 状态；这些不能进入正式译文。

真实回复包含标准五列表格。现有 AX 正文扁平化与纯文本显示不能保留该表格，需要从获取、翻译到显示共同保存结构。

## 设计与边界

1. 仅在已验证的 Code 消息区内，将明确的流式容器接到它前面的、具有作者标题的用户消息，暂用下一消息编号；编号正式出现后沿用同一身份。缺用户锚点、重复流式容器或冲突编号继续等待。Chat 作者识别不放宽。流式活动尾栏与工具卡保持排除。
2. 普通 AX 表格按行和单元格恢复为 Markdown。数字、分隔符、代码、URL 和公式留在本地；仅单元格中的语言文字进入翻译。翻译后重建相同行列，不靠模型重画表格。宽表在伴侣内横向滚动，可复制为 Markdown。无法确定结构的复杂合并表格不编造行列。
3. 正文显示、代码围栏与长文滚动保持原行为。表格渲染使用原生视图，不执行 HTML 或远程内容。稳定表格更新与普通段落共用版本、取消和排队保护。

## 完成检查

- 先写复现用例，确认旧行为失败，再修复；覆盖流式身份、完成后身份连续、工具过滤与不确定结构。
- 表格覆盖 AX 行列、中文表头、数字/代码保护、转义竖线、非法列数、代码围栏中的伪表格；在纯本机模拟界面查看宽表、滚动和复制。
- 全应用回归、独立构建和仓库检查通过后，按原签名安装 build38；保持偏好与原辅助功能授权。
- 第一任务保留失败记录；用已有真实表格核对，不再生成它。剩余第二任务检验中文阶段在整轮结束前出现、60 秒停顿和后台读取。任何服务错误单列，不能只用原文证明翻译通过。
- 本批仍最多两个 Claude 任务；Gemini 请求尝试 30、源字符 30,000 为上限。网页、CLI、长文在线专项不顺带验收。

## build39 补充修订

build38 在已完成的真实回复中成功恢复五列、五行数据的表格，但独立表头的 Spread 被 Gemini 译成金融领域的“价差”。为保持统计学词义，每个单元格只携带附近正文和表格语言文字组成的上下文（最多 1,200 字符），不传表格数字、受保护代码、公式和 URL。上下文是用户数据，系统规则继续限定只翻 source_text；按任务隔离，不能跨表格或回复串用。预算字符计数包含上下文。

真实结果列表的 CSV 按钮此前被误判为工具活动，导致整列表隐藏。仅补充 CSV、TSV 文件引用规则，不放宽所有按钮。独立符号与纯数字段在本地保留，避免无意义请求。

本批已经消耗 23 次请求；第二任务继续研究有偏分配与测量误差，用三段短正式回复、三列数值统计表检验实时回译与 Spread 词义。行标签使用数值，避免额外模型调用；预计六次请求，失败或多余拆分仍计入 30 次上限。第一任务的及时性问题保留为失败记录，不重发第一任务。

## 2026-10-06 补测后本地修订

第三任务单独获得授权，累计尝试上限提高为 40，字符保持 30,000。实测确认第一阶段中文在整轮结束前出现；表格词义仍失败，第二阶段没有中文，后台专项未完成。目标切换期间的额外请求造成全批 71 次超限，已停止，不擅自追加在线验证。

本机复现确认 `ReplyPipeline.update` 从已译前缀之后重新解析，会丢失表格身份及语境。修订对完整原文解析，仅在取得带结构信息的片段后裁除已译前缀。验证重复轮询、尾部追加、数字行追加、不重复已译表头、保留数字和单元格转义。原 build39 证据保留；修订本地模拟和构建通过后作为独立候选，不在这次已停止的真实批次中安装。
