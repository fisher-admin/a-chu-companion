# A畜伴侣应用身份清理

目标：当前源码、正式包、测试包和本机可运行副本统一使用 A畜伴侣的名称与身份，保留用户已有设置和翻译密钥。

完成标准：当前源码与二进制没有旧名称；正式包只有一个可执行文件；旧应用副本、测试临时文件、偏好设置、钥匙串项目及系统应用登记已移除；迁移后的设置保持一致；回归测试通过；新版能打开并完成中译英。

1. 关闭应用，记录相关设置的键名与存储状态，不输出设置值或密钥。
2. 先运行身份检查，确认能发现旧名称与多余文件。
3. 正式应用使用 `local.achu.companion` 与 `AChuCompanion`；测试应用使用 `local.achu.fixture`。更新测试路径、文档和快捷键内部签名。
4. 从全新临时包构建、签名并校验成功后替换正式包，避免保留旧可执行文件。
5. 用一次性的本地工具迁移偏好设置与钥匙串项目。目标内容与源内容核对成功后，才移除源项目。
6. 注销旧应用登记，移除已确认属于本项目的旧副本、缓存与测试文件，仅重置本应用的旧授权。
7. 运行身份扫描、核心/编辑器/回复/HTTP 测试、签名检查；打开新版，核对设置并实际翻译。
8. 新身份的辅助功能授权需要用户通过 macOS 正常权限界面确认。不能以编译成功代替权限和跨软件流程验证。

不改写 Git 历史，不删除操作系统常规历史日志、用户对话或其他项目文件。已确认属于旧版临时测试的诊断报告随临时测试工具清理。历史记录不会参与新版运行。

追加目标：解决辅助功能添加失败与升级后授权失效。

9. 建立专用本机签名证书，将不可导出的私钥保留在登录钥匙串，仅允许系统签名工具使用。签名绑定应用标识与证书指纹，不退回临时签名。
10. 将正式程序安装到固定的用户应用目录，更新时检查原身份、签名和替换结果，只保留正式安装的应用登记。
11. 用两份代码不同的程序验证身份连续性，验证冒充、篡改和配置缺失均会失败。
12. 最后为固定签名版本重新确认一次辅助功能，验证应用重启、内容发生变化的更新及再次重启都保留授权。整台 Mac 重启留待用户安排。
13. 应用运行期间每秒检查辅助功能状态，授权变化即时更新页面；不依赖窗口激活、不重复申请权限、不自动捕获或发送。用实际异步轮询验证授权、撤销、停止和重启监测，并核对草稿与本地消息不变。
